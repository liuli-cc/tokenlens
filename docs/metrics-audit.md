# 用量指标核验记录

核验日期：2026-09-30。本文记录可读取的数据、修正的计算问题和仍然存在的边界。它不包含账号、密钥、会话标识、对话内容、工具输出或原始日志。

## 显示规则

- `--` / 未提供表示来源没有返回该指标，不能解释成 0。
- Token、缓存、调用数以本机可读取记录为范围；云端其他电脑、未记录用量的失败请求和被删除的日志无法补齐。
- 最近调用是最近 7 天记录到的用量事件。Codex 无独立请求 ID 时，这是记录次数下界，不是服务器账单的完整请求数。读取器不会仅因重复的额度通知而新增一次调用。
- 缓存命中率为“缓存读取 Token ÷ 全部输入 Token”。缓存创建属于输入，但不属于命中；推理 Token 已包括在输出时不会再加一次。
- `≈` 表示上下文估算。Codex 和 Harness 使用最近一次模型响应的输入加输出总量及该请求报告的上下文窗口；它们不是会话累计消耗。后续工具消息、提示修改和压缩可能改变当前占用，日志没有新的报告时无法得到精确实时值。
- 配额是账号采样值，不能通过本地 Token 数推算。主、次窗口分别保留；胶囊取尚未重置、未超过 15 分钟的窗口中最少剩余的那个。超过采样时限、缺少重置时间或已过重置点时显示未知，不自动猜成 100%。
- 余额只接受账号服务或受支持的官方余额接口。登录状态未知、读取失败和超过 3 分钟未更新的 Harness 余额隐藏，赠金同样隐藏。成功获取时间与尝试请求时间分别记录。

## GPT / Codex

来源为本机 `sessions/**/*.jsonl` 的 `token_count`、`turn_context`、会话身份和明确任务生命周期；不解析提示文本或工具输出。

此次直接检查 8 份近期真实日志的元数据，在 1,215 个 Token 通知中发现 74 次累计量重复。实际字段包括 `cache_write_input_tokens`、`primary`、`secondary` 和额度桶标识。部分分叉日志含两条会话身份记录；第二条是继承的记录，不能据此把子任务误判为用户主会话。

已修正：

1. 仅对累计 Token 的增量计数；重复累计值不新增消耗或调用，累计值下降时开启新的计数周期，保留此前消耗。
2. 分叉复制的同一用量事件在汇总中只计一次；读取第一条身份记录，子任务继续计入本机用量，但不替换用户主会话的模型、上下文或完成反馈。
3. 同等长度重写日志也重建扫描缓存，防止保留旧计数。
4. 仅带额度、`info=null` 的通知仍能更新配额；缓存率在两端统一为当前会话的全部可读消耗口径。
5. Codex 在上下文耗尽时可生成“总量=上下文窗口、输入和输出=0”的合成通知。它保留满上下文提示，但不加入已消耗 Token 或调用数。
6. 当前模型变化时先清除旧模型的上下文窗口；窗口未返回前显示未知。
7. 无用量记录的完成事件显示未返回，不再显示假 0；当前官方 Codex 会话不会被 CC Switch 旧配置覆盖为另一个提供商的余额；外部模型会话也不会继承旧官方额度，没有来源可证的余额时显示不可读取。
8. 配额桶 ID、名称、采样时间、两个窗口与重置时间均保留。账号共享额度的前后差值无法归因到某一任务，因此不再把它当成本轮任务的准确额度消耗。

独立交叉核验：Codex 应用的只读额度服务与最新本机日志返回了同一额度桶、38% 已用、10,080 分钟窗口及相同重置时间；该时点两者均对应 62% 剩余。这个核验确认该次采样一致，不保证离线后的数值一直最新，也不消耗重置权益。

GPT 岛读取的是 Codex 会话记录；它无法自动读取 ChatGPT 普通网页聊天的 Token 账单。

## DeepSeek Harness

检查了这台电脑安装的 Harness **0.2.0-rc.2** 所带官方模块：`dsh-agent-loop`、`dsh-session`、`dsh-token-meter` 和 `dsh-client-ui-chat`。当前三份近期 v4 日志只有配置和会话初始化事件，没有真实模型响应的 usage，因此目前不能声称已经核对过真实 DSH Token 消耗。

读取器现支持：

- `assistant/message.data.usage`；失败或中断的 `assistant/attempt` 在 stream 内返回 usage 时也计入。
- `request/context.data.contextWindow`，模型及提供商选择元数据。
- usage 中的 `inputTokens` 为未命中输入；`cacheReadTokens` 和 `cacheWriteTokens` 另计。总输入优先从 `totalTokens-outputTokens` 取得，并与已知分项校验；全部分项齐全时才允许由分项求和。
- reasoningTokens 不再加到输出或总量中；缓存分项缺失时不会把缺失值假装成 0%。
- `session/end-seed` 前的继承历史不算新调用；同一持久化事件按会话与 seq 去重。仅根会话决定主状态，取消、错误或 max-tokens 不触发“任务完成”。
- 账户桥每 60 秒请求官方余额，保存成功获取时间；离线或失败不能用一次新尝试的时间把旧余额伪装为最新余额。

有实际 usage 后显示真实返回值；没有时保持未知。上述接口兼容性已通过合成回归验证，不能代替真实账号账单对比。

## CC Switch 外部提供商

直接只读检查发现本机数据库具有 `input_token_semantics` 字段：代理日志有 7,790 行旧语义和 985 行全输入语义，汇总表 142 行为已归一化的未命中输入语义。旧实现对所有记录直接加 `input + cache_read + cache_creation + output`，会把缓存重复算进 Codex 代理用量。

已按 CC Switch 官方 `sql_helpers.rs` 的三种语义处理：0 为旧缓存读取包含在输入，1 为缓存读写都包含在输入，2 为缓存读写不包含在输入。先归一化未命中输入，再计算完整输入和输出。优先使用真实代理记录，排除合成或重复导入数据，范围统一最近 7 天。

余额请求仅发送到支持的官方 HTTPS 主机（DeepSeek / Moonshot），拒绝重定向，不猜测未公开的信用余额接口。没有支持的接口就显示不可读取。代理若提供 session_id，则本轮费用只使用匹配的会话；旧库没有会话身份时的时间与模型匹配只能称为费用估计，不能替代提供商账单。

## 回归检查与证据界限

Swift `ScannerSelfTest` 覆盖增量刷新、重复累计、计数周期重置、分叉身份和事件去重、用户主会话优先、两窗口额度、采样过期及 CC Switch 缓存语义。`DeepSeekMetricsSelfTest` 覆盖真实接口形状的 usage、缓存分母、继承 seed、重复事件、失败尝试和余额过期。Windows 的相应测试覆盖同一计算与未知状态规则。

合成回归验证计算和状态处理；真实日志结构检查验证本机现有版本兼容性；官方只读配额对比验证一个采样时点。三种证据不能相互替代。
